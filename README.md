# 課堂檢核系統：架設教學

學生用學校 Google 帳號（@student.ksvs.kh.edu.tw）登入、勾選檢核項目並上傳檔案或填寫文字；教師在後台看各班即時完成率、每次上課（日期＋作業編號）的紀錄，並可匯出 Excel。

整個系統免費，架設一次大約 30～40 分鐘。

---

## 一、系統架構（先看懂再動手）

| 部分 | 放在哪裡 | 作用 |
|---|---|---|
| 資料庫 | 您 Gmail 帳號裡的 **Google 試算表** | 存班級、學生、作業、繳交紀錄 |
| 後端程式 | 試算表內的 **Apps Script**（`gas/Code.gs`） | 驗證登入、讀寫資料、存上傳檔案到雲端硬碟 |
| 網頁 | **GitHub Pages**（免費網站空間，`web/` 資料夾） | 學生頁 `index.html`、教師後台 `admin.html` |
| 登入 | **Google Cloud 的 OAuth 用戶端 ID** | 讓網頁可以用「使用 Google 帳號登入」 |

**為什麼網頁不直接放在 Apps Script 裡？** 您用個人 Gmail 架設、學生用學校網域帳號登入，屬於「跨網域」。這種情況下 Apps Script 內建的方式拿不到學生的 Email，所以改用標準的「使用 Google 帳號登入」按鈕，網頁需要一個固定網址，GitHub Pages 正好免費提供。

---

## 二、建立試算表與後端程式

1. 用**您要架設的那個 Gmail 帳號**登入，到 [Google 試算表](https://sheets.google.com) 新增一份空白試算表，取名例如「課堂檢核資料庫」。
2. 上方選單 **擴充功能 → Apps Script**。
3. 把編輯器裡原本的程式全部刪掉，貼上 `gas/Code.gs` 的全部內容，按 💾 儲存。
4. 左側 ⚙️ **專案設定**：
   - 「時區」選 **(GMT+08:00) 台北**。
5. 回到編輯器，上方函式下拉選 **`setup`**，按 **▶ 執行**。
   - 第一次會跳出授權：選您的帳號 → 「進階」→「前往（不安全）」→「允許」。這是您自己的程式，可以放心。
   - 執行完回到試算表，會看到 5 個工作表：班級、學生名單、作業、繳交狀態、提交紀錄；雲端硬碟也會出現「學生檢核_上傳檔案」資料夾。
6. **專案設定 → 指令碼屬性**，確認或修改：

   | 屬性 | 值 |
   |---|---|
   | `TEACHER_EMAILS` | 您的教師 Gmail（多個用逗號分隔），預設已填架設帳號 |
   | `STUDENT_DOMAIN` | `student.ksvs.kh.edu.tw` |
   | `CLIENT_ID` | 先留著，第三步拿到後再填 |

7. 把「班級」工作表的範例班級（一年1班～一年7班）改成您實際的 7 個班名（之後也能在後台改）。

## 三、建立「Google 登入」用的用戶端 ID

1. 用同一個 Gmail 開啟 [Google Cloud Console](https://console.cloud.google.com/)，上方「選取專案」→「新增專案」，名稱例如 `classroom-check`，建立後切換到該專案。
2. 左側選單 **API 和服務 → OAuth 同意畫面**（新版介面叫 **Google Auth Platform**），按「開始」：
   - 應用程式名稱：例如「課堂檢核」
   - 使用者支援電子郵件：您的 Gmail
   - 目標對象：**外部**
   - 聯絡資訊：您的 Gmail → 建立
3. 左側 **目標對象**，發布狀態按 **「發布應用程式」** 改成「實際運作中」。
   - ⚠️ 這步很重要：停在「測試中」的話，只有您手動加入的測試使用者能登入。
   - 本系統只用到 Email 與姓名這種基本權限，**不需要送 Google 審查**。
4. 先完成第四、五步拿到網站網址後，再回來做這步：左側 **用戶端 → 建立用戶端**
   - 應用程式類型：**網頁應用程式**
   - 已授權的 JavaScript 來源：新增 `https://sylviakang.github.io`（不要加結尾斜線、也不要加 /helper）
   - 建立後複製「用戶端 ID」（長得像 `1234-abcd.apps.googleusercontent.com`）。
5. 回到 Apps Script 的 **指令碼屬性**，把 `CLIENT_ID` 改成剛複製的值。

## 四、部署後端（Apps Script 網頁應用程式）

1. Apps Script 右上角 **部署 → 新增部署作業**，齒輪選 **網頁應用程式**：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
2. 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。
3. 用瀏覽器打開這個網址，看到 `{"ok":true,"message":"學生檢核系統 API 運作中"}` 就成功了。

> 之後若修改 Code.gs，要到 **部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**，網址不會變。只改指令碼屬性則不用重新部署。

## 五、網站（GitHub Pages）

網頁檔案已經放在 GitHub repo **sylviakang/helper**，網址是：
- 學生頁：`https://sylviakang.github.io/helper/`
- 教師後台：`https://sylviakang.github.io/helper/admin.html`

1. 如果打開上面網址是 404：到 repo 的 **Settings → Pages**，Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾 `/ (root)`，Save，等 1～2 分鐘。
2. 回到第三步第 4 點建立用戶端 ID，「已授權的 JavaScript 來源」填 `https://sylviakang.github.io`。
3. 在 GitHub 上點開 `config.js` → ✏️ 編輯，填入：
   ```js
   API_URL: '第四步的 /exec 網址',
   CLIENT_ID: '第三步的用戶端 ID',
   ```
   Commit 後等約 1 分鐘生效。

> repo 裡的 `gas/Code.gs` 是後端程式的備份，要貼到 Apps Script 才會生效；放在網站上不會被執行，也沒有機密資料。

## 六、測試

1. 打開教師後台，用您的教師 Gmail 登入 → 看得到四個分頁就成功。
2. 「作業設定」→ 新增一個作業，勾選班級。
3. 用一個學生帳號（或請一位學生）打開學生頁 → 第一次會要求登記班級、座號、姓名 → 勾選並送出。
4. 回後台「即時完成率」就看得到。

### 如果學生登入時出現「存取權遭封鎖」或「管理員已封鎖」

這是學校 Google Workspace 管理員限制了第三方應用程式。請學校資訊組在 **管理控制台 → 安全性 → API 控制項 → 應用程式存取權控管 → 管理第三方應用程式存取權 → 設定新應用程式**，搜尋您的用戶端 ID，設為「信任」即可。只要設定一次。

## 七、日常使用

**每次上課**
1. 後台「作業設定」→「＋新增作業」：作業編號會自動帶下一號（HW01、HW02…），日期預設今天。
2. 填檢核項目（一行一項），選擇「上傳檔案或照片」與「文字回覆」是不需要／選填／必填，勾選適用班級。
3. 學生打開學生頁就會看到。上課結束可按「關閉」，學生就不能再改。
4. 同樣的作業要給其他班或下次再用，按「複製」最快。

**判定「已完成」的規則**：所有檢核項目都勾選，且必填的檔案／文字都有提供。學生可以在作業開放期間重複送出修改。

**後台功能**
- **即時完成率**：選作業，看各班完成率，點班級看每位學生的狀態、文字和檔案連結。開著頁面每 30 秒自動更新。
- **班級總表**：一個班的所有學生 × 所有作業（可選日期範圍），一眼看出誰常缺交。
- **作業設定**：新增、編輯、複製、開放/關閉、刪除。
- **班級與學生**：改班級名稱；從 Excel 貼上名單預先匯入（Email、班級、座號、姓名四欄）；修改或移除登記錯誤的學生。
- **匯出 Excel**：一份檔案包含「完成率總覽」、每班一張總表、「繳交明細」。

**學生上傳的檔案**存在您雲端硬碟的「學生檢核_上傳檔案 / 作業編號_標題 / 班級」資料夾，檔名自動加上班級、座號、姓名。

**原始資料**都在試算表裡，「提交紀錄」工作表保留每一次送出的時間與內容摘要，方便查證。

## 八、常見問題

- **學生說登記錯班級或座號**：後台「班級與學生」→ 修改。
- **學生名單完成率分母不對**：分母是該班「已登記或匯入」的學生數。學期初建議先匯入名單，未登入的學生才會算成「未繳交」。
- **容量**：Google 試算表可存 1000 萬格，以 7 班 × 40 人 × 每學期 40 次作業計算，用好幾年都沒問題。Apps Script 免費帳號每天可處理約 2 萬次請求，全班同時送出也足夠。
- **安全性**：每次操作後端都會向 Google 驗證登入憑證；只有 `@student.ksvs.kh.edu.tw` 能使用學生功能，只有 `TEACHER_EMAILS` 能進後台。`config.js` 裡的用戶端 ID 本來就是公開資訊，放在公開網站沒有問題。
